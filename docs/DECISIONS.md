# Architectural decisions

This is the authoritative decision log for the phase 0.0 specification baseline. Accepted decisions remain in force until superseded by a later numbered entry.

| ID | Status | Decision |
|---|---|---|
| D-001 | Accepted | Python is the reference implementation; pure Python remains supported. |
| D-002 | Accepted | `hedron` is the FastAPI flagship distribution; Flask and Django use separate adapters. |
| D-003 | Accepted | `HedronRoute`, `HedronRouter`, response classes, lifespan, middleware, DI, StaticFiles, and OpenAPI hooks are the integration foundation. |
| D-004 | Accepted | `hedron-core` imports no FastAPI, Flask, Django, ASGI, or WSGI types. |
| D-005 | Accepted | JSON endpoints return models; HTML endpoints return components. |
| D-006 | Accepted | `Hedron()` may be a convenience application, but it is a thin composition of FastAPI extension points, not a parallel runtime. |
| D-007 | Accepted | Components are renderable by default; addressability and public exposure are explicit. |
| D-008 | Accepted | HTMX is the default request/swap layer; Web Components own persistent browser-local interaction. |
| D-009 | Accepted | Hedron-owned `Model`, `Props`, `FormModel`, and `Field` expose a constrained Pydantic-backed type system. |
| D-010 | Superseded | HDN was selected as an optional advanced language; D-039 reopens whether Hedron should own a separate declarative language at all. |
| D-011 | Accepted | Scoped styles use structural CSS rewriting, stable names, external assets, and light DOM by default. |
| D-012 | Accepted | The Component Explorer uses the same registry as rendering, routing, OpenAPI, tests, and assets. |
| D-013 | Accepted | Security is cross-cutting: contextual escaping, explicit trusted types, CSRF, safe URLs, private authenticated caching, and production-disabled Explorer. |
| D-014 | Accepted | Async I/O is supported at endpoints, dependencies, actions, sources, and plugin lifecycles; rendering stays synchronous until evidence requires otherwise. |
| D-015 | Accepted | The required dependency set stays small; integrations are lazy extras or separate packages. |
| D-016 | Accepted | DataEditor uses typed change sets and a Web Component; Tabulator is the initial default adapter. |
| D-017 | Accepted | `Auto()` uses an ordered, inspectable renderer registry and always permits explicit override. |
| D-018 | Superseded | Rust acceleration and cross-language bindings are deferred until contracts stabilize and benchmarks justify them. Superseded by D-048 for phase 0.14. |
| D-019 | Accepted | General streamed HTML is deferred; lazy addressable components are the default deferred-loading pattern. |
| D-020 | Accepted | Durable work belongs to external job systems; FastAPI `BackgroundTasks` is used only for small post-response work. |
| D-021 | Accepted | Hedron exposes scoped cache decorators and Streamlit-inspired utility components while leaving cache services, storage, and durable state to the application ecosystem. |
| D-022 | Superseded | The original pre-1.0 roadmap used cumulative releases 0.1 through 0.9; D-031 replaces only that numbering. |
| D-023 | Superseded | The initial matrix was CPython 3.12–3.14 with FastAPI `>=0.141.1,<0.142`, Pydantic `>=2.13.4,<2.14`, and bundled HTMX 2.0.10. Python range superseded by D-034. |
| D-034 | Accepted | Supported CPython is 3.11–3.14 (`requires-python = ">=3.11,<3.15"`). FastAPI `>=0.141.1,<0.142`, Pydantic `>=2.13.4,<2.14`, and bundled HTMX 2.0.10 remain as under the compatibility policy. |
| D-024 | Accepted | Hedron uses the documented monorepo distribution/import layout; Explorer is installed through `hedron[dev]`, not required by production `hedron`. |
| D-025 | Accepted | `@app.page`/`@router.page`, `@app.component`/`@router.component`, and `@app.action`/`@router.action` are the canonical app-local decorators. `@addressable` defines a reusable component resource that becomes reachable only through `include_component`. |
| D-026 | Accepted | Public code renders through opaque `ComponentNode`/`NodeLike` contracts and `render(...) -> RenderResult`; concrete serializer nodes and the serializer implementation remain private in 0.x. |
| D-027 | Accepted | Logical IDs are readable namespaced identifiers; generated instance and asset IDs use versioned SHA-256-derived formats with collision checks as specified in `IDENTIFIERS.md`. |
| D-028 | Accepted | The phase 0.1/0.2 built-in component catalog is fixed by `api/BUILT_INS.md`; later data, utility, and chart catalogs remain assigned to their roadmap phases. |
| D-029 | Accepted | The repository uses a uv workspace, Hatchling, Ruff, Pyright, pytest/pytest-anyio, and the configuration and diagnostic contracts documented for 0.0. |
| D-030 | Superseded | No open-source license is inferred; license selection blocks public publication but not local phase 0.1 implementation. Superseded by D-033. |
| D-031 | Superseded | The specification phase is 0.0 and the former stable target was phase 1.0. D-038 removes that target. |
| D-032 | Superseded | Established the original phase-to-release mapping through `v1.0.0`. D-038 retains `0.N` → `v0.N.0` but removes the scheduled 1.0 terminus. |
| D-033 | Accepted | Hedron is licensed under the MIT License; the repository root and each publishable distribution ship `LICENSE` with matching package metadata. |
| D-035 | Accepted | Phase 0.7 retains the `v0.7.0` train but is governed by a phase 0.6 behavioral closure gate and staged internal gates: portable adapter foundation, FastAPI operations, Flask, Django, jobs/conformance, and an optional-transport decision. Portable semantics are shared; ASGI, WSGI, and framework-native differences are explicit capability claims. Completion from phase 0.6 onward requires linked automated or immutable evidence; checked prose alone is not release evidence. Its former 1.0 release-train clause is superseded by D-038. |
| D-036 | Superseded | Django QuerySet as a first-party `hedron-data` DataSource is Deferred for the `v0.7.0` Supported adapter claim. Apps may bridge QuerySets themselves; Hedron does not advertise QuerySet paging/security as a portable contract until a later decision. Superseded by D-046 for phase 0.11. |
| D-046 | Accepted | Phase 0.11 ships a first-party bounded Django QuerySet `DataSource` in `hedron-data`. Applications supply an already-authorized base QuerySet; Hedron never discovers models or calls `.objects.all()` from user input. Ordering, filtering, projection, search, and page size are allowlisted; tenant/auth scoping is applied before client refinements and cannot be removed. Evaluation is forbidden at import, startup, diagnostics, and schema description. Query budgets, transaction ownership, and sync/async evaluation rules are explicit capability contracts. Flask Blueprint/`init_app`, Django `AppConfig`, Django forms bridging, portable adapter test harnesses, HDJ dynamic manifests/CSP reconciliation, Celery/RQ `JobBackend` bridges, and capability-labeled Flask/Django live helpers are in scope for `v0.11.0` as specified by ROADMAP §0.11 and D-044. |
| D-037 | Accepted | Phase 0.7 external cache and durable job conformance targets Redis (`redis` client, JSON `h1:` keys). FastAPI `BackgroundTasks` remains non-durable (D-020). Official HTMX SSE was Deferred through 0.9; phase 0.10 ships pinned `htmx-ext-sse` as **experimental** live observation while bounded polling remains the required Supported fallback (RFC-0032 / JOB-006; see What’s ready). |
| D-044 | Accepted | Phase 0.10 live transports follow RFC-0032: official SSE, focused streaming primitives only (D-019), page/session WebSocket channels for declared regions/client reads with HTTP/SSE/polling fallbacks, and opt-in navigation preload. Live/preload never becomes a hidden correctness dependency. FastAPI is the Supported host; Flask/Django live depth remains 0.11. |
| D-045 | Accepted | Phase 0.10 ships `Dialog`, `ChatMessage`, and `ChatInput` plus timed media chunk **transport** contracts. Chat history and model-provider state remain application-owned. First-party camera/microphone/Audio/Video capture UI remains phase 0.15. |
| D-038 | Accepted | Hedron has no scheduled 1.0 phase or arbitrary API-freeze terminus. Capability phases continue on the `0.x` line (`0.N` → `v0.N.0`), with stability and compatibility promises attached to documented contracts rather than inferred from a major version. The former deferred backlog is assigned through phases 0.9–0.14; D-041 subsequently swaps the 0.9 and 0.11 authoring/native-framework priorities. Every phase retains evidence, migration, and published-artifact gates. This supersedes D-031/D-032 and the 1.0/freeze portions of D-035. |
| D-039 | Superseded | Placed the experimental HDN language/runtime on a ground-up design hold; D-040 selects the replacement and retains the HDN deprecation boundary. |
| D-040 | Superseded | Selected optional Jinja authoring and a staged HDN removal; D-041 keeps the replacement but removes the compatibility schedule. |
| D-041 | Accepted | Phase 0.9 replaces HDN immediately with the separate optional `hedron-jinja` distribution. Python components remain canonical; Jinja templates are trusted application code with explicit component bindings and strict defaults. HDN source discovery, parser/evaluator/formatter, render program, artifacts, public APIs, CLI/Explorer paths, examples, and tests are removed with no compatibility flag, converter, or legacy package. Version 0.8 is the final HDN-capable line. Block component syntax uses explicit `with body` to avoid an ambiguous Jinja grammar. |
| D-042 | Superseded | Defined standards-first HDJ without a distinct file format; D-043 retains the standards-first boundary but makes `.hdj` an explicit versioned format. |
| D-043 | Accepted | `.hdj` is the canonical Hedron Jinja template format. A mandatory, static TOML prologue declares format version, template kind, a named feature profile, additional feature IDs, required deployment capabilities, assets, and fragment regions; the remaining body is ordinary Jinja/HTML. Feature declarations improve tooling and production inventory but never authorize routes/actions or weaken SecurityPolicy/CSP. HDJ loaders accept `.hdj` sources; ordinary Jinja files remain usable outside HDJ or through an explicitly declared foreign-template boundary. |
| D-047 | Accepted | Phase 0.12 owns data and visualization scale: advanced DataEditor (formulas, merges, pivots, trees, collaborative editing, spreadsheet I/O beyond CSV), shared column catalog with display-versus-write policy, typed grid/chart events and saved views, explicit `TransformPlan` with Explorer visibility, Dask/Snowflake bounded sources, beginner Area/Bar/Scatter charts, Plotly typed events, annotation overlays, and the named optional visualization adapters (Vega-Lite, PyDeck, MapLibre, Folium, GraphViz, Mermaid, Chart.js, Great Tables, Sigma/NetworkX, Three.js, ECharts, Datashader, Bokeh, HoloViews/hvPlot, Pygal, Plotly resampling). Optional adapters ship as first-party extras with local-asset/CSP/payload/lifecycle/accessible-fallback contracts. HDJ `hedron.data`/`hedron.charts` provider parity is in scope. Phase cut `v0.12.0` requires every `release-gate-0.12.toml` row Verified with zero Deferred, including three-engine browser and a11y matrices. AG Grid claims cover Community client and infinite row models only. |
| D-048 | Accepted | Phase 0.14 lifts D-018 under evidence gates: a published language-neutral conformance-test kit is the cross-language contract; experimental Java and Node runtimes and optional Rust acceleration may ship when they pass that kit. Pure Python remains the semantic reference and Supported fallback (D-001). Native acceleration requires named bottleneck, target improvement, benchmark corpus, parity suite, reproducible wheels/source-build, memory-safety/fuzz evidence, and material end-to-end benefit. Runtime or accelerator absence never changes public semantics, security policy, or deterministic output. HDJ exact loop/macro instrumentation, contracted extension evidence, scoped-style/validated-attribute helpers, broader contextual analysis, and portable checker fixtures close `HDJ-DEF-014` while preserving Jinja semantics and a pure-Python fallback. |
| D-049 | Accepted | Phase 0.18 ships model-demo/inference contracts on the Beta train (hedron-core/hedron 0.18.0): InferenceInterface/ModelDemo (fail-closed, registered actions only), ExampleSet/presentation/feedback, InferencePolicy over JobBackend, interaction recorder, and typed inference workflows with structured non-canvas editor. Optional hedron-gradio ships as independent Alpha 0.1.x with no core cost when absent. Deliberate non-parity: mutable globals, default-public UI APIs, raw JS injection, cwd file exposure, share tunnels, host-code editing. Feedback never silent or ground truth. In-process queues are development-only. |

## Phase 0.7 entry blockers

Entry blockers for adapter implementation (COMPATIBILITY ranges, evidence ledgers, core ownership,
Explorer acyclic deps) are closed for the `v0.7.0` train. Remaining work is staged gates 0.7A–0.7F.

Changes to accepted decisions require an explicit superseding decision and affected RFC/API updates.
